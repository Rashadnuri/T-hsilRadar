# TəhsilRadar — Product Specification

Status: Draft v0.1 (documentation phase, no code yet)
Languages: Azerbaijani (default), Russian, English

## 1. Vision

TəhsilRadar is a multilingual platform that helps students, graduates and young professionals discover **verified** educational and career-development opportunities in Azerbaijan and abroad. Azerbaijan is a first-class market: local government programs, universities, banks, IT companies and NGOs are treated as equal to international opportunities, not as an afterthought.

## 2. Goals

| # | Goal | Measure of success (MVP + 6 months) |
|---|------|-------------------------------------|
| G1 | Be the most trustworthy place to find opportunities relevant to Azerbaijanis | 100% of published items have an official source link and a verification record |
| G2 | Reduce discovery time | A user finds and saves a relevant opportunity in under 3 minutes |
| G3 | Serve users in their language | All UI in AZ/RU/EN; opportunity pages clearly state which languages their content exists in |
| G4 | Help users act, not just browse | Saved items and application tracking used by ≥30% of registered users |
| G5 | Keep operations sustainable for a small team | One admin can review ~30 submissions/week with the tooling provided |

### Non-goals (for now)
- We do not process applications on behalf of users. We link to the official source.
- We do not predict admission or award outcomes.
- We do not host or sell courses, nor charge applicants.
- No native mobile apps (responsive web only; PWA is a later option).
- No user-to-user social features.

## 3. Product principles (binding)

1. **Trust first.** Every published opportunity has an official source URL and a named organization. No source → cannot be published.
2. **No fake data.** Demo/seed content is flagged `is_demo = true`, shown with a visible "Demo" label, and excluded from production by default.
3. **No invented content.** Missing translations are shown as missing (with fallback to the original language, clearly labelled), never fabricated. Facts (dates, amounts, eligibility) are never generated by AI.
4. **Honest AI.** Match scores express *profile-to-criteria fit*, never admission probability. Wording and UI must say so.
5. **Freshness.** Expired opportunities are never displayed as active.
6. **Mobile-first.** Primary use is on phones; every flow must work at 360px width.
7. **Security and data integrity** are requirements, not features (see SECURITY.md).

## 4. Target users

| Persona | Description | Main needs |
|---------|-------------|-----------|
| **Aysel, school-leaver / bachelor applicant** (17–19) | Looking at universities, summer schools, olympiads | Simple language, deadlines, what documents are needed |
| **Murad, undergraduate/graduate** (19–24) | Seeks internships, scholarships, exchange | Filter by field, country, funding; track deadlines |
| **Leyla, young professional** (22–30) | Wants certifications, courses, masters, research | Career relevance, cost, format (online/in-person) |
| **Russian-speaking user** | Prefers RU interface; often from the Russian-speaking segment of Baku or regions | Full RU UI; honest indication when content is only in AZ/EN |
| **Organization / contributor** | University, NGO, company wanting to list an opportunity | Simple submission, clear review status |
| **Admin / moderator** (internal) | Verifies and curates | Review queue, source checking, duplicates detection, translation tooling |

## 5. Opportunity types

Scholarship · Internship · Grant · University admission · Exchange program · Training · Certification · Summer school · Hackathon · Competition · Research program · Other.

"Other" requires a free-text type label so it can be reviewed and promoted to a real type later. The full field list, funding types, location types and statuses are defined in DATA_MODEL.md §3.4.

Each opportunity also carries: market scope (`azerbaijan` | `international` | `both`), provider type (government, university, bank, private company, IT company, NGO, international organization, other), funding type (fully funded, partial, paid by participant, stipend, unknown), format (online, onsite, hybrid), and eligibility fields (education level, fields of study, nationality/residency rules, age range, language requirements).

## 6. Main user journeys

### J1 — Anonymous discovery
1. Lands on `/az` (or language detected from first visit; see INTERNATIONALIZATION.md).
2. Sees featured/closing-soon opportunities and category tiles.
3. Searches or filters (category, country, deadline, funding, level, field, language).
4. Opens a detail page: summary, eligibility, deadline, benefits, documents, **official source link**, verification badge, "last verified" date.
5. Clicks "Go to official site" (outbound link; recorded as an aggregate click count).
6. To save or track, is prompted to register.

### J2 — Registration and profile
1. Registers by email + password or Google (Supabase Auth); email verification required.
2. Short onboarding (skippable): education level, field, graduation year, nationality/residency, languages, interests, preferred countries.
3. Profile editable at any time; user can delete their account and data.

### J3 — Save and track
1. Saves an opportunity (bookmark).
2. Moves it into application tracking with a status: *interested → preparing → applied → interview → accepted / rejected / withdrawn*.
3. Adds private notes, personal reminder date, checklist of documents (MVP: notes + status + dates).
4. Sees a dashboard sorted by upcoming deadline. Opportunities that expire stay in the user's tracker, labelled "Expired".

### J4 — AI matching
1. Authenticated user with a profile opens "Recommended for you".
2. Server filters eligible, active opportunities with deterministic rules, ranks them, and optionally asks the LLM to produce short explanations.
3. Each card shows a **match level** (e.g. "Strong / Good / Partial fit") with reasons *and gaps* ("You meet the field requirement; the IELTS 6.5 requirement is not in your profile").
4. A permanent disclaimer: "This is a profile-fit indicator, not a prediction of selection."

### J5 — AI assistance on a detail page
User asks "Am I eligible?", "Summarize in Russian", "What documents do I need?". The answer is grounded only in that opportunity's stored fields, cites which field it used, and says "not specified in the source" when information is missing. Machine-generated summaries are labelled as AI-generated and are never saved over official content.

### J6 — Submission
1. A signed-in contributor submits an opportunity via a form (including official URL and organization).
2. It enters `pending_review`; the submitter sees its status.
3. An admin verifies, edits, and publishes or rejects with a reason.

### J7 — Admin curation and import
1. Admin opens the review queue (submissions, imports, reported items).
2. Checks the official source, fills verification checklist, adds/edits translations, sets deadline.
3. Publishes. Items auto-expire after the deadline passes.
4. Bulk import (CSV/JSON, later scrapers) produces *draft* records only, always with source URL, never auto-published.

### J8 — Language switching
User switches language from any page; stays on the equivalent page (`/az/opportunities/xyz` → `/ru/opportunities/xyz`), filters preserved in the query string.

## 7. Feature requirements

Priority: **M** = MVP, **L** = later.

### 7.1 Multilingual interface (M)
- AZ/RU/EN for all UI strings, validation messages, emails, SEO metadata, date/number formats.
- Localized URLs, language switcher, `hreflang`. Details in INTERNATIONALIZATION.md.

### 7.2 Catalogue and search (M)
Implemented; the full URL contract and semantics are in ARCHITECTURE.md §7.
- Paginated list (6 per page) with sort: **deadline approaching** (default), **newest**, **recently updated**, and **relevance** (when searching).
- Search across title, organization, keywords (type/field/level/place labels in all three languages) and description; diacritic- and case-insensitive; works on mobile (visible search box, search keyboard, no zoom).
- Filters, all combinable: **country, city, opportunity type, education level, academic field, funding type, remote/onsite/hybrid, application deadline, verification status**, plus a **dedicated Azerbaijan / International switch**.
- **Azerbaijan is easy to find:** the Azerbaijan tab (with counts) opens a panel with Azerbaijani cities (Baku, Sumgait, Ganja, Mingachevir, Shaki, Nakhchivan, …) and shortcuts for local scholarships, internships and grants.
- Filter state lives in the URL (shareable), is kept across pagination, sorting, language switching, and the detail page's back link. Active filters appear as removable chips.
- **Expired items are never shown as active.** They appear only when asked for (Deadline = Expired) and look clearly different. Their detail page stays reachable by link and explains that the opportunity ended.
- Rolling-admission and unknown-deadline items are supported and labelled as such.
- Loading (skeleton and "updating" state) and empty states (empty catalogue vs. no match, with a reset action).
- Content appears in the selected language when available; otherwise the **original** is shown with its language named. Nothing is silently substituted (INTERNATIONALIZATION.md §6.4).

### 7.3 Opportunity detail (M)
Implemented: localized title; short and full description; organization; location (type, city, country); eligibility text plus structured levels, fields and countries; requirements; benefits; funding (type, amount and period, percentage, and the participation fee kept separate); deadline and start date in the organization's time zone; **official source URL**; **verification status** (with the date when verified; demo records say "not verified"); available languages; and an **application button** that opens the organization's own application page in a new tab (`rel="noopener noreferrer nofollow"`). The button is disabled when applications are closed or not open yet, and warns when no deadline is stated. Every section that is not in the selected language is labelled with its real language. Demo items carry a visible banner.

### 7.4 Authentication & profile (M)
Email/password + Google OAuth via Supabase Auth, email confirmation, password reset, profile CRUD, language preference stored, account deletion.

### 7.5 Saved opportunities (M)
Toggle save, list with filters, works across devices.

### 7.6 Application tracking (M)
Status pipeline, notes, personal dates. Reminders by email (L).

### 7.7 AI matching (M-lite / L-full)
- MVP: rule-based eligibility + score; LLM explanation text on demand, cached.
- Later: embeddings-based semantic similarity (pgvector).
- See ARCHITECTURE.md §8 for guardrails.

### 7.8 AI assistance (M-lite)
Grounded Q&A and translation-draft help limited to one opportunity; rate-limited; logged without storing unnecessary personal data.

### 7.9 Admin dashboard (M)
Review queue, opportunity editor with per-language tabs, translation status indicators, verification checklist, organizations management, user-report inbox, demo-content toggle, audit log view.

### 7.10 Verification (M)
Defined statuses and checklist; see DATA_MODEL.md and SECURITY.md. Public badge: "Verified on <date>" with the source link.

### 7.11 Submission & import (M submission / L import tools)
Submission form (M). CSV import by admin to drafts (M-lite). Automated source monitoring/scrapers (L).

### 7.12 Notifications (L)
Email digests, deadline reminders, new-match alerts. Requires explicit opt-in and unsubscribe.

## 8. Content rules

- Source-of-truth: the organization's official page. We store `official_source_url`, `original_language` (any ISO 639-1 code), and a snapshot of key facts at time of verification.
- Required for publishing (see DATA_MODEL.md §6.4): organization, opportunity type, official https source URL, an **original-language** version with title and short description (other languages optional), a deadline **or** an explicit "rolling/unknown" type, and `verified_by` + `last_verified_at` (demo records are exempt but flagged).
- Translations are `original`, `human`, or `machine_draft`. Machine drafts are not shown publicly unless an admin approves them, and then are labelled "Machine-translated".
- Prohibited: placeholder real-organization names in demo data. Demo data uses clearly fictional organizations (e.g. "Demo University") and `is_demo = true`.
- Any user-visible "AI" content is labelled.

## 9. Non-functional requirements

- **Performance:** LCP < 2.5 s on mid-range mobile over 4G for catalogue and detail pages (server-rendered, cached).
- **Accessibility:** WCAG 2.1 AA target; keyboard navigable; proper `lang` attribute per page.
- **SEO:** SSR/ISR, localized metadata, sitemap per locale, structured data (`JobPosting`/`Event`/`Course` where appropriate, otherwise `WebPage`) only when data is accurate.
- **Availability:** Reasonable for a startup (managed Vercel + Supabase); no SLA promised at MVP.
- **Privacy:** Data minimization; compliance posture described in SECURITY.md.
- **Browser support:** Last 2 versions of evergreen browsers, iOS Safari 15+.

## 10. MVP scope

**In:**
- AZ/RU/EN UI and localized URLs
- Catalogue, search, filters, detail pages
- Auth (email + Google), profile, onboarding
- Save + application tracking (status, notes, dates)

- CSV import to drafts

- Basic analytics (privacy-friendly, aggregate)

**Out (deferred):** email reminders, embeddings search, scrapers, org self-service portal, mobile app, payments/promoted listings, comments/reviews, CV builder, calendar sync, additional languages.
